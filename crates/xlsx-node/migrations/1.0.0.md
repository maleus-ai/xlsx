# Migrating to 1.0.0

Every change below is breaking. Apply them in order; each one stands alone, and the last section of each says how to check it held.

## peek-sheets — `listSheets` is `peekSheets`

**Detect** — `rg -n "\blistSheets\b" --type ts --type js`; the compiler reports that `@maleus/xlsx` has no exported member `listSheets`.

**Change**

```ts
// before
import { listSheets } from "@maleus/xlsx";
const sheets = await listSheets(path, { maxDecompressedBytes });
// after
import { peekSheets } from "@maleus/xlsx";
const sheets = await peekSheets(path, { maxDecompressedBytes });
```

**Behaviour** — none: same parts read, same budget, same refusals. The sheets it returns change shape — see `sheet-info-state`.

**Verify** — `rg -n "\blistSheets\b"` finds nothing; the type check passes.

## read-rows — `xlsxRows` is `readRows`, `XlsxRowsOptions` is `ReadRowsOptions`

**Detect** — `rg -n "\bxlsxRows\b|\bXlsxRowsOptions\b" --type ts --type js`.

**Change**

```ts
// before
import { xlsxRows, type XlsxRowsOptions } from "@maleus/xlsx";
const options: XlsxRowsOptions = { maxDecompressedBytes, maxRows };
const rows = xlsxRows(path, options);
// after
import { readRows, type ReadRowsOptions } from "@maleus/xlsx";
const options: ReadRowsOptions = { maxDecompressedBytes, maxRows };
const rows = readRows(path, options);
```

**Behaviour** — none on its own; what the stream yields changes — see `row-object`. The class is still `XlsxRows`.

**Verify** — `rg -n "\bxlsxRows\b|\bXlsxRowsOptions\b"` finds nothing; the type check passes.

## row-object — a row is `{ row, values }`

**Detect** — every consumer of a `readRows` stream: `for await` loops over it, `pipeline` stages after it, `on("data")` handlers. The compiler reports indexing or array methods (`row[0]`, `row.length`, `row.map`) on `Row`. Plain JavaScript gets no compiler help: search for the stream's consumers by hand.

**Change**

```ts
// before
for await (const row of xlsxRows(path, options)) {
  insert(row[0], row[1]);
}
// after
for await (const { row, values } of readRows(path, options)) {
  insert(values[0], values[1]);
}
```

A `Transform` that receives the rows changes the same way: read `chunk.values` where it read `chunk`.

**Behaviour** — `row` is the 0-based position of the row in the sheet. Rows the file does not carry are not emitted, so `row` skips over them: a counter kept by the consumer drifts from the sheet after the first gap. Replace any such counter with `row`, and show `row + 1` to a person — that is the line number the spreadsheet displays.

**Verify** — the type check passes; an import test that reports a line number on a sheet with an empty row in the middle reports the line the spreadsheet shows.

## sheet-info-state — `SheetInfo.visible` is `state`, and `sheetId` is new

**Detect** — `rg -n "\.visible\b" --type ts --type js` near a call to `peekSheets`, `listSheets` or `.sheets()`; the compiler reports that `visible` does not exist on `SheetInfo`.

**Change**

```ts
// before
const shown = sheets.filter((sheet) => sheet.visible);
// after
const shown = sheets.filter((sheet) => sheet.state === "visible");
```

**Behaviour** — `state` is `"visible"`, `"hidden"` or `"veryHidden"`. `visible: false` covered the last two; code that only cares whether a sheet shows compares to `"visible"`. `sheetId` is the identifier the workbook gives the sheet, not its position: keep using the array index for the tab order. A deep equality on a `SheetInfo` now sees two more keys and one fewer.

**Verify** — `rg -n "\.visible\b"` finds no `SheetInfo` access; the type check passes.

## unknown-sheet-state-corrupt — a sheet state outside the format is refused

**Detect** — code that catches `XlsxError` from `peekSheets`, `readRows` or `.sheets()` and branches on `code`. Nothing fails to compile.

**Change** — where the code already handles `CORRUPT` from these calls, nothing. Where it only expected `CORRUPT` from reading rows, make sure the same branch also covers the sheet list:

```ts
try {
  const sheets = await peekSheets(path, budget);
} catch (error) {
  if (error instanceof XlsxError && error.code === "CORRUPT") {
    return rejectUpload("the workbook is damaged");
  }
  throw error;
}
```

**Behaviour** — a workbook whose `<sheet>` declares a `state` other than `visible`, `hidden` or `veryHidden`, or no numeric `sheetId`, is refused with `CORRUPT`. 0.5 read such a sheet as hidden. Excel itself refuses these files.

**Verify** — the upload tests still pass; no test relied on a malformed `state`.

## write-workbook — `xlsxWriteStream` is `writeWorkbook`, `XlsxWriteStreamOptions` is `WriteWorkbookOptions`

**Detect** — `rg -n "\bxlsxWriteStream\b|\bXlsxWriteStreamOptions\b" --type ts --type js`.

**Change**

```ts
// before
import { xlsxWriteStream } from "@maleus/xlsx";
await pipeline(source, xlsxWriteStream({ sheet: "Export" }), destination);
// after
import { writeWorkbook } from "@maleus/xlsx";
await pipeline(source, writeWorkbook({ sheet: "Export" }), destination);
```

**Behaviour** — none. The class is still `XlsxWriteStream`.

**Verify** — `rg -n "\bxlsxWriteStream\b|\bXlsxWriteStreamOptions\b"` finds nothing; the type check passes.

## sheet-row-values — a row naming its sheet carries `values`, not `data`

**Detect** — objects written to a `writeWorkbook` stream with a `sheet` key: `rg -n "sheet:.*data:" --type ts --type js`. TypeScript reports `data` as an unknown property on `SheetRow` only where the object is typed; a generator that yields untyped objects compiles and fails at run time.

**Change**

```ts
// before
yield { sheet: "Q2", data: [client.name, client.signedAt] };
// after
yield { sheet: "Q2", values: [client.name, client.signedAt] };
```

**Behaviour** — a row object with `data` and no `values` is refused with `INVALID_VALUE` and the message `is not a row`. Writing places each row right after the previous one of its sheet: it ignores any `row` position. To copy a row read with `readRows`, pass on its `values` alone — as a bare array, or as `{ sheet, values }` — and expect the empty rows of the source to be gone from the copy, every row after a gap moving up.

**Verify** — an export test that writes to two sheets passes and reads both back.

## error-code-open-union — `XlsxErrorCode` is open

**Detect** — `switch` statements or exhaustive maps over `error.code` of an `XlsxError`, especially ones relying on TypeScript's exhaustiveness check (`never` in a default branch).

**Change**

```ts
switch (error.code) {
  case "DECOMPRESSED_BUDGET_EXCEEDED":
  case "TOO_MANY_ENTRIES":
    return tooLarge();
  case "CORRUPT":
  case "NOT_AN_ARCHIVE":
    return damaged();
  default:
    // A minor version may add a code.
    throw error;
}
```

**Behaviour** — a minor version may add a code. An exhaustive `switch` without a default branch would miss it without failing to compile.

**Verify** — every `switch` over `XlsxError.code` has a default branch.
